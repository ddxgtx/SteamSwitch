# 歌曲控制栏动画优化（2026-10-22）

问题：控制栏展开时，歌词右边距使用 ThicknessAnimation 逐帧变化，反复触发测量、布局和文字省略计算；控制栏同时缩放、淡入、平移并带阴影。

调整：

- 歌词最终宽度仅布局一次，通过反向位移保持起始视觉位置，再使用 RenderTransform 平滑让位。反向进入/离开从当时的位置和透明度继续，重复事件不重启动画。
- 控制栏保持最终尺寸，只播放 6 DIP 位移和透明度过渡，位移进入/退出分别 160/120ms，淡入/淡出分别 110/90ms（此前进入位移 220ms、淡入 200ms）。
- 歌词和控制栏使用局部位图缓存；移除包裹整条任务栏内容的阴影以及控制栏浮层的模糊阴影，保留玻璃材质和边缘高光。
- 封面悬停缩放缩小为 1.03 倍、140ms；退出后的布局冻结持续 160ms，覆盖退出动画。

验证：在 conda hot 中 Release 构建成功，0 警告、0 错误，196/196 测试通过。

`UiCapture <output> lyrics-hover-profile 900 150 Light|Dark` 使用隔离配置创建不激活的屏外 WPF 窗口，以真实动画时钟采样，并统计歌词子树的 Measure/Arrange 和 Margin 变更。浅色优化前四轮进入/退出分别为 18/19/21/17 次重排，优化后浅色与深色每轮均为 1 次。

双主题另外验证了 6 次动画中途反向、6 次重复事件、160 DIP 窄歌词区域的可读性及交互恢复。原有歌词稳定性检查通过，包括 80 次媒体更新、80 次事件合并、固定宽度/字号、封面与副行稳定、悬停隔离、切歌和关闭后拒绝更新。彩色背景的 WPF 控制栏最终状态渲染已检查。

数据和图片：`.codex-qa/hover-animation-20261022/`，其中 `before.json` 为优化前计数，`after-Light.json` / `after-Dark.json` 为优化后计数。

范围：上述结果证明布局工作量减少和状态过渡正确，不是实际 Explorer 桌面的帧率测量。真实任务栏上的流畅度、显示器刷新率和系统合成表现仍需运行新版体验确认。
