# 配置持久化故障检查与修复（2026-10-22）

本轮检查快速启动、游戏绑定、配置恢复和最近的备份/设置改动。现有更新下载代码已在提交前关闭写流，相关首次下载/校验/取消测试继续通过，没有把历史审计中的旧问题重复计作本轮修复。

## 发现与修复

| 问题 | 可复现结果 | 修复 |
|---|---|---|
| 快速启动读取失败标记不会在重读成功后复位 | 修复 JSON、重新加载并新增条目后，重新从磁盘加载仍只有原条目 | 成功读取完整快照后解除写入保护 |
| 游戏绑定读取失败被吞掉并清空记录 | 损坏 JSON 后加载不报失败，内存原绑定消失，后续写入可能覆盖磁盘历史 | 读失败保留最后有效快照、上报错误，成功重读前禁止修改 |
| 两类集合写入失败被当作成功 | 独占目标替换权限时新增操作正常返回、发布变更事件，内存状态与磁盘不一致 | 读取、修改和写入共用闸锁；修改独立快照，原子写入完成后才提交到内存及发布成功事件 |
| 空记录、JSON null 与重新加载并发不安全 | 空记录可导致部分替换或静默清空；重读与编辑交错可导致 UI 与磁盘快照不同 | 验证完整读取结果后提交；读写串行；查询接口返回独立快照 |
| 固定按钮默认双向绑定提前改变状态 | 保存失败时按钮及列表模型可能仍显示已固定 | 改为单向显示持久化状态，并在点击完成后刷新目标绑定 |
| 删除中间快速启动项后新增产生重复排序值 | 新条目的 Count 排序值与已有条目冲突 | 追加前按现有顺序归一化排序值，确保追加位置唯一 |
| 游戏已启动后，游玩记录写入失败会影响启动结果 | 新的显式持久化错误若直接向上传递，会跳过退出监控并被外层误报为启动失败 | 单独处理启动后的记录错误，告知用户记录未保存，继续原有监控流程 |

两类集合保持现有 JSON 文件格式。写入失败不会用半完成编辑替换已发布状态；从有效配置恢复后可继续编辑。界面已有的错误捕获现在能得到真实保存错误。
