# 多账号库入口强化（2026-10-22）

现有 AccountLibraryService 已按 Steam ID 独立保留本地账号资料，将 Steam 当前记录里缺失的账号合并显示为本地历史账号。本轮重点改善功能存在感和历史账号查找，不新增密码或登录凭据存储。

界面调整：

- 将主导航和页面命名为“多账号库”，将原来分散的指标卡改为醒目的“多账号保存 · 自动收录”功能区。
- 一屏提供“收录账号”“待找回”“导入账号库”“备份账号库”，同时展示本地收录、Steam 当前记录、待找回数量。导入/备份复用已有的账号元数据流程。
- “待找回”清除旧搜索条件、筛选本地历史账号，并显示首个账号的找回操作；“查看全部”清除筛选和旧搜索，避免账号被旧条件隐藏。没有本地历史账号时禁用待找回入口。
- 将容易与游戏存档混淆的“已存档”文案改为“仅本地记录 · 待找回”。配置内部继续使用 Archived 值，兼容既有设置。
- 明确仅保存账号资料、不保存密码，找回后 Steam 可能要求密码或验证码。

验证环境：conda hot。Release 独立输出在 `artifacts/account-library-20261022/Release/net8.0-windows10.0.19041.0/`。

验证结果：

1. Release 构建成功，0 警告、0 错误，197/197 测试通过。
2. 新增持久化回归：保存 100 个账号，模拟 Steam 只保留 5 条记录，重新加载后仍保留 100 个账号，其中 95 个以本地历史记录形式可查；账号库导出、导入和再次加载均保留 100 条记录。该场景是模拟数据，不表示 Steam 实际上限为 5。
3. 双主题、1120×760 与 1360×900 的 `account-library-guidance` 均通过：入口在可见边界内；额外 100 个历史账号能按昵称、登录名及 Steam ID 精确搜索；待找回入口清除旧搜索并显示正确记录；查看全部恢复列表；无待找回记录时禁用入口。该 UI 检查没有执行登录、导入或导出文件对话框。
4. 双主题 `main-guidance` 仍通过。WPF 渲染检查覆盖全部、待找回、当前账号及空列表状态，图片位于 `.codex-qa/account-library-20261022/`。

范围：本地持久化与隔离 WPF 界面测试；未执行真实 Steam 登录或实机鼠标交互。启动新版前需从托盘完全退出旧实例，避免单实例机制将请求转发给旧窗口。
